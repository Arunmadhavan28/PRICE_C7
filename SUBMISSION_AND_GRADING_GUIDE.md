# Autonomous PR Submission, Evaluation, and Completion Guide

This guide explains the end-to-end autonomous evaluation system for the Retail AI Lab repository (`Arunmadhavan28/PRICE_C7`). 

The entire grading, bot commenting, pull request review, and code merging process is 100% autonomous. You do not need manual verification from an instructor to get evaluated. When your code achieves 100/100 points (25.0/25 marks), the automated system approves and merges your Pull Request directly into `main`.

---

## 1. Overview of the Autonomous Pipeline

When you open or update a Pull Request targeting the `main` branch, the GitHub Actions autograder runs through the following sequence within 60 to 90 seconds:

```
[Student Opens / Updates PR]
              |
              v
[GitHub Actions Triggered (pull_request_target)]
              |
              v
[Automated Unit Tests Run (pytest)]
              |
              v
[Autograder Evaluates 5 Pillars (evaluator/autograder.py)]
              |
              v
[Bot Posts / Updates Sticky Scorecard Comment on PR]
              |
    +---------+---------+
    |                   |
[Score < 100]      [Score == 100 (25.0/25 Marks)]
    |                   |
[Bot Submits Review:    [Bot Submits Review: APPROVE]
 COMMENT (Needs Work)]  |
    |                   v
[Student Fixes Code     [Bot Executes Autonomous Squash Merge into main]
 and Pushes Again]      |
                        v
                   [Bot Posts Completion Confirmation]
                        |
                        v
                   [Student Notifies ARUNMADHAVAN]
```

## 2. Step-by-Step Instructions for Students

This workflow is structured so that students from any academic background (including arts, commerce, and humanities) can complete it without confusion.

### Step 1: Fork the Repository
1. Visit https://github.com/Arunmadhavan28/PRICE_C7
2. Click the **Fork** button near the upper-right corner.
3. Select your GitHub username as the destination.

### Step 2: Clone Your Fork Locally
Open your terminal (Terminal on macOS / Linux, or Git Bash / PowerShell on Windows) and run:
```bash
git clone https://github.com/YOUR_GITHUB_USERNAME/PRICE_C7.git
cd PRICE_C7
```

### Step 3: Create a Dedicated Feature Branch
```bash
git checkout -b team-submission
```

### Step 4: Set Up Python and Dependencies
Ensure you have Python 3.10 or higher installed:
```bash
python3 -m venv venv
source venv/bin/activate       # On Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Step 5: Implement Your Team Track
All work for your assigned track takes place exclusively inside your assigned team folder:
- Team 1: `teams/team01_vibe_shift/`
- Team 2: `teams/team02_sassy_stylist/`
- Team 3: `teams/team03_dynamic_pricing/`
- Team 4: `teams/team04_color_shopper/`
- Team 5: `teams/team05_empathy_engine/`
- Team 6: `teams/team06_markdown_optimizer/`
- Team 7: `teams/team07_ethical_auditor/`
- Team 8: `teams/team08_tryon_analytics/`
- Team 9: `teams/team09_artisan_stock/`

### Step 6: Verify Locally Before Submitting (Crucial Step)
You can run the exact same autograder locally on your computer before pushing. For example, if you are on Team 1:
```bash
# 1. Run the team unit tests
pytest teams/team01_vibe_shift/tests/ -v

# 2. Run the autograder
python evaluator/autograder.py --team 1
```
Check that your local output reports:
`Raw Score: 100/100 | Final Marks: 25.0/25 | Status: PASS`

### Step 7: Commit, Push, and Open a Pull Request
```bash
git add teams/team01_vibe_shift/
git commit -m "feat(team01): completed vibe-shift trend forecaster"
git push origin team-submission
```
1. Go to your repository on GitHub.
2. Click **Contribute** -> **Open pull request**.
3. Ensure base repository is `Arunmadhavan28/PRICE_C7` and base branch is `main`.
4. **Fill out the PR Template and Check All Task Boxes**:
   - In the PR description, fill in your team members and prompt logs.
   - In the **Self-Evaluation Checklist**, mark every item with `[x]` (e.g. `- [x] Architecture...`).
   - Leaving boxes empty (`- [ ]`) causes GitHub to show an incomplete grey badge. Marking all `- [x]` enables the official purple `tasks done` completion badge upon merge.
5. Submit the pull request.

## 4. What If Your Score Is Less Than 100?

If your score is less than 100 (e.g. 85/100):
1. Read the **Diagnostic Checks** in the bot comment.
2. Look for items marked with `[FAIL]` or `[WARN]`. Common reasons include:
   - Missing unit test coverage or failing test assertions.
   - Missing columns in your dataset.
   - Incomplete Prompt Log in your team `README.md`.
3. Fix the issue locally in your editor.
4. Run `python evaluator/autograder.py --team X` locally to verify the fix.
5. Commit and push to the same branch:
   ```bash
   git add .
   git commit -m "fix: updated prompt log and test cases"
   git push origin team-submission
   ```
6. The bot will automatically detect the new commit, re-run evaluation, and update the scorecard comment.

## 6. Frequently Asked Questions for Non-Technical Students

### Do I need to pay for any cloud hosting or API services?
No. All mock datasets and algorithmic models are built-in and free. If your team utilizes an optional Gemini API key, the Google AI Studio free tier provides 15 requests per minute at zero cost.

### Can I submit multiple times if I make a mistake?
Yes. You can push commits as many times as needed to your feature branch. The autograder runs on every push and updates your score immediately.

### What if my Pull Request shows merge conflicts?
If someone else modified the same file, GitHub will flag a conflict. To prevent this, only work inside your assigned folder (`teams/team0X_.../`). Never modify root files or other teams' folders.
